# Prepared automation and checkpoint storage

The Mac portable control service's admitted 100,000-point automation edit could make a later Play fail with “Prepared mutable DSP state exceeds 128 MiB budget.” Admission multiplied the entire authored session JSON by 32 and treated it as mutable checkpoint storage. Every worker fork/checkpoint also cloned authored tracks, effects and automation strings.

Worker preparation now projects authored tracks/effects into playback-only fields. Immutable envelopes retain source placement and fade/crossfade values; history, names, instrument recipes and unknown metadata remain in the authoritative project model. Resolved envelope/config/pitch-region storage is shared through `Arc`. Automation lanes use compact frame/value/curve-domain/curve-enum points, sorted stably with the original last-duplicate-wins semantics. Interpolation arithmetic, decibel scaling and pitch-region boundary semantics are unchanged.

The aggregate prepared graph admission limit remains **128 MiB**, excluding separately admitted source PCM. Admission bounds the projected immutable lane/envelope/config representation plus independent mutable DSP history, scheduling state and scratch. Prepared graphs expose `immutable_storage_budget()` and `mutable_storage_budget()`. Forks and checkpoints share the immutable allocations and independently copy mutable histories. Standalone `checkpoint_storage_budget()` conservatively includes shared data a checkpoint can retain after graph retirement, protecting the existing 256 MiB cache limit even across graph revisions. Admission has not been increased to make the fixture pass.

The regression prepares three 100,000-point lanes and 1 MB of editor-only metadata. It verifies authored metadata survives projection, mutable storage is independent of lane density, actual allocation bytes/counts for dense forks and checkpoints equal those for sparse forks/checkpoints, repeated Play/Pause is callback-confirmed, dense seeks remain bounded, and the callback allocates/retires nothing. Another regression retains the 128 MiB aggregate rejection using real prepared pitch-processor admission.

All existing Swift-generated DSP, envelope, gain, pitch, loop, seek and paged callback references remain the acceptance baseline. These are source/worker/callback-simulation results. Actual service/browser acceptance and hardware timing/listening qualification remain separate gates owned by the Mac integration workflow.
