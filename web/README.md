# Soundroom browser client

The browser controls a Soundroom hardware server. Recording, instruments, effects and playback run on that server; this client opens no audio/MIDI devices and provides no browser monitoring.

## Build

Node 18+ and TypeScript 5.3+ are required. With registry access, run `npm install` in this directory, then:

```sh
npm test
npm run build
```

A globally installed `tsc` also works. The runtime has no third-party dependencies and the build produces static `dist/` assets. The Soundroom server hosts those assets over HTTPS. A layout-only development server is available with `npm run dev`; live control still requires a trusted WSS endpoint and approved origin.

After a protocol schema change, run `node tools/sync-contract.mjs` from this directory. `src/generated/contract.ts` and `src/validate.ts` mirror the canonical root `protocol/` artifacts; do not change wire fields independently.

## Trusted LAN mode (HTTP/WebSocket)

For a trusted private LAN, keep `build/Soundroom-Rust.app` running on the hardware Mac and run:

```sh
cd web
npm run dev:lan
```

Open one of the printed `http://HOST:5174/` addresses. The connection endpoint is filled automatically with `ws://HOST:5174/control`. Create a fresh code in the native app's **Server connection → Browser access**, using the same client name in the browser. Code lifetime defaults to 30 minutes in the updated native GUI, with 2-minute and 1-hour choices. The host retains its 2-minute default for clients that omit a lifetime. Choose Operate when audio transport is needed. Pairing codes and individual role checks remain active; transport is unencrypted and relies on the LAN being trusted. This mode does not provide TLS confidentiality or protection against a hostile LAN peer.

The gateway serves the built browser assets, accepts private IPv4/loopback peers only, validates the Host and same-origin WebSocket upgrade, and forwards only `/control` to the fixed local Rust server. The internal connection still verifies the generated local CA; no browser/system trust changes or native server restart are required. It does not expose project/credential directories or forward to a caller-selected destination. Secure WSS remains the default SDK policy; plaintext is enabled only by this gateway's configuration for the page's exact origin and control path.

HTTP LAN browsers lack `crypto.randomUUID` and `SubtleCrypto`. Client IDs use cryptographic `getRandomValues`, and the existing HMAC-SHA256 proof has a tested SHA-256 fallback. In trusted LAN mode, **Remember this browser** saves the individual credential and client name in this origin's browser storage after verified authentication. Reloads reconnect with that credential; it has no automatic expiry. **Disconnect** keeps the remembered pairing; **Forget this browser** clears it and the in-memory credential. The native operator can revoke its access. Clearing browser data or changing the page hostname/port requires pairing again. Secure-host credentials stay in memory by default. `SOUNDROOM_LAN_PORT`, `SOUNDROOM_SERVER_PORT` and `SOUNDROOM_CA` can override the local ports/CA file. IPv6-only LANs and public peer addresses are not supported in this mode. Stop the gateway with Ctrl+C. Initial upgrade/authentication failures stop instead of retrying a single-use code. An established connection permits at most three automatic reconnect attempts per manual Connect. The gateway records only bounded transport-stage/error-code diagnostics in `build/QA/trusted-lan-runtime-20261012.json`, never credentials or message bodies.

## Connect

Open the HTTPS URL displayed by the hardware host. The host supplies `/soundroom-config.json` with `wssURL` and no secrets. Certificate trust must be established through the host’s documented workflow; the client never disables certificate checks.

Choose **Connect**, enter your client name and a short-lived code approved by a server operator. The alternative is an existing pairing file. Pairing credentials remain in memory and disappear on page close/reload; they are never stored in browser storage or placed in URLs. Each page has an independent runtime client identity. Reconnection uses that identity and obtains a fresh session before editing resumes.

The current endpoint uses WebSocket subprotocol `soundroom.v3`, versioned JSON commands and HMAC-SHA256 challenge proof. Roles are assigned by the server. Imported legacy credentials discard the shared legacy transport PSK; only the individual client secret is retained in memory.

## Arrangement and controls

- Space plays/pauses the server; typing in a field or dialog keeps normal typing behavior.
- Click the ruler to place the private cursor. Drag an audio lane to select a range and intersecting clips. Shift-click extends clip selection. Drag past the viewport edge to scroll.
- Drag selected clip edges to trim with source bounds and a live waveform preview. Right-click a clip for contextual editing and history. Inspector controls edit exact start/end/source, fades, edge protection and overlap crossfades. Alt-drag a clip to move it. **S** splits the selected clip at the cursor. Delete removes selected clips. **Combine** sends the selected clip group to the server.
- **+ / −** zoom around the viewport center. Ctrl/Cmd-wheel zooms around the pointer. Horizontal or Shift-wheel scrolls; ordinary wheel scrolls tracks. Manual navigation turns Follow off.
- Time/Beats, Snap, Follow, cursor/range fields, zoom and selection stay private. Tempo and meter edit the shared project. A 123 BPM grid snaps to absolute sample boundaries rather than accumulating interval rounding.
- Track controls provide arm, mute, solo, gain, pan, input device and channel. Session input/output menus route server devices; each track has mono/stereo selection. The recording setup arrow provides count-in, pre-roll, punch-to-range, compensation offset, metronome and server monitoring, with armed input routes visible before starting. Record uses this client’s saved setup; Finish completes the server take. Track names can be renamed by double-clicking.
- **Import** reads a file from this computer, computes incremental SHA-256, uploads acknowledged 256 KiB chunks, and imports at the cursor. Cancel prevents further chunks/finalization; partial uploads are discarded on disconnect. Resumable uploads are not implemented.
- Cmd/Ctrl-C/X/V copies, cuts and pastes audio; the **Edit** menu also copies tracks with or without automation. Track pasting renews track, clip, take, insert and pitch identities, aligns to the cursor and preserves clipped nonlinear automation. Cmd/Ctrl-T trims to the range, Cmd/Ctrl-L aligns, and arrows nudge (Shift: one second). Clip history restores a prior state or creates a track at the original timeline location. Clipboard audio stays on its original hardware server.
- **Projects** lists managed server projects and explicitly confirms reopening for the shared session. **Save** saves a managed server project. **Export** renders and downloads a checked WAV artifact. Chrome/Edge with the File System Access API stream verified exports to disk with bounded chunks (up to the server’s 2 GiB limit). Browsers without a disk stream use a 256 MiB bounded Blob fallback and explain larger-file limits.
- The live effect rack uses server-advertised parameter names, units, bounds and choices. Inline **Expand** opens grouped precision controls, normalized logarithmic sliders and physical fields with correct percentages and discrete choices. EQ/filter curves, dynamic transfer, saturation, delay, room decay, modulation and quantization graphs are labelled settings models; spectral suppression and insert meters come from actual server measurements. Factory and custom browser presets, Track/Master scope, Play track/Play mix, add, enable, adjust, remove, and **Apply to audio** all send real commands; baking uses the authoritative live-insert path, retains automation, and avoids applying inserts twice.
- Track **A** opens an automation drawer for volume, pan and advertised effect parameters. Add/drag/delete points, edit exact positions and physical values, select interpolation curves, and smooth the lane. **Read automation** remains available; continuous **Write** is explicitly disabled until the host provides audio-clock-stamped gesture capture. Ordinary live fader changes coalesce with one history gesture and never author points from the client’s display clock. Explicit chart edits use reviewed frame positions.
- **Pitch** opens a dedicated analysis workspace for the selected range, clip or track. Input/output contours, fixed pitch viewport, time and pitch zoom, voiced-region point insertion, drag/exact numeric edits, curves/smoothing, calibrated target names, native stabilized target presets, processing presets, Original/Audition and live-target activation use the server’s actual analysis and processing. Applying closes the workspace only after a successful atomic bake. Dense target curves use indexed interpolation.
- **Master** measures the full server mix and reviews integrated LUFS, true peak, crest, tonal energy and section graphs. The server returns its exact conservative proposal and verifies the source fingerprint. You can include inserts and tune every advertised parameter before atomic application; smooth section automation remains editable through the Master rack. A changed mix disables a stale proposal.
- Cmd/Ctrl-Z performs authored Undo; Shift adds Redo. Conflicts produce server feedback and refresh metadata. Failed/uncertain mutations are never automatically replayed.

## Performance and integrity

The canvas indexes immutable clip arrays once and draws visible tracks/clips and viewport ruler ticks. Mixer DOM is limited to visible rows. Meter and transport messages do not replace clip/note arrays. The playhead interpolates locally, with a 500 ms stale-telemetry limit; it does not schedule audio. Waveform display caches are bounded to 8 MiB and preserve complete overview coverage alongside finer tiles. Dependent mutations wait for the authoritative metadata revision when a priority receipt arrives first; a timeout refreshes metadata without replaying the mutation. The SDK bounds pending requests and the browser send buffer, reserving capacity for Stop. Paged snapshots have a 64 MiB ceiling, contiguous offsets, a pinned revision and verified SHA-256; partial snapshots are never installed. Deltas arriving during assembly are bounded and applied after the verified revision.

Standard MIDI format 0/1, running status, channels/controllers, bounded excerpt clipping, dense-file review, malformed/variable-tempo rejection and keyboard names are covered too. These are SDK/model checks, not substitutes for real browser/network/hardware acceptance.

This is a functional arranging foundation. Beats provides kits/pattern presets, step toggles, per-hit velocity/probability/pan/articulation, lane tuning/damping/gain/pan/mute, swing/humanization/variation, a private 32-pattern bank with new/duplicate/copy/paste, native `.soundroomdrums` file import/export, timing-preserving grid changes, local draft Undo/Redo and coalesced live audition updates. Playback/live keyboard are operator-only; editor clients can draft and insert.

Full browser parity remains open: server-shared preset libraries, continuous server-stamped automation Write and advanced automation range/Touch/Latch operations, full keyboard accessibility review, shared Designer preset libraries, drum WAV export and advanced Beats actions, additional measured spectral visualizers, accessibility listening/keyboard review and measured 60 Hz performance. No placeholder advanced workspace is advertised as implemented. Windows/Linux browser review, mixed-client LAN acceptance, and real browser recording/import/export checks remain explicit release gates.

Server MIDI capture currently uses event arrival timing in the browser and the server preview clock. It preserves received note-on velocity, but it is not a sample-accurate hardware recording path; server-stamped event capture remains a parity gate.

## Browser interaction harness

`npm run test:webkit` builds the real UI and runs macOS WKWebView against an explicit injected test-only transport fixture (100 tracks and 10,000 clips). It checks visible mixer row bounds, scroll/Follow/cursor separation, clickable anchored zoom, focus-safe Space, inline effect expansion and physical edits, recording setup, Designer keyboard and audition routing, server MIDI names, and Beats step interaction. It records frame counts/gaps without claiming a universal 60 Hz result. The fixture is recursively checked by the ordinary Node suite and is never included in production assets. The custom local WK scheme avoids opening a listening socket; its authentication is deliberately mocked, so it cannot establish WSS trust or security acceptance.

The execution sandbox currently denies macOS WebKit child services, so the interaction harness has not passed here. Run it from the normal developer terminal; real browser/native-host trust, hardware audio, pointer capture, accessibility, Windows and Linux remain separate acceptance checks.

Designer custom sounds can be saved/deleted in bounded browser storage or imported/exported as native `.soundroom-preset.json` files. Saving excludes notes/controllers and loading preserves the current sequence and tempo. Native numeric `seed`/`organicSeed` UInt64 fields are lexed into decimal strings before JSON parsing and exported back as exact native integer tokens, avoiding JavaScript precision loss. A dedicated controller chart edits all retained sustain/modulation/expression/pitch-bend points with held-event display, zoom/scroll, drag, exact beat/value fields and keyboard deletion/nudging. Layer enable, velocity bounds, sound overrides and exact seed overrides, base mix and keyboard octave controls are available. Custom sound storage is local to the browser; shared library/chain management remains a server capability gap.

**Manage saved** in an insert or **Manage chains & presets** in the rack opens a private browser library. Effect presets use the native version-1 document (`id`, `name`, `kind`, `parameters`, optional `legacyAmount`); chain files support native versions 1 and 2. Import/export, save/replace settings, rename/delete and a separate bounded library Undo are implemented. Existing older browser custom presets remain visible. Files are validated against advertised effect parameters, including physical bounds and discrete choices; unknown fields/kinds, duplicate fields/identities/names and oversized files reject rather than silently altering settings. Effect files are limited to 1 MiB, chains and browser storage to 4 MiB, 128 entries per library and 64 inserts per chain.

Applying a parameter preset keeps the target insert’s identity, automation, pitch edits and rendered-audio guards. A legacy preset sends its original amount and empty parameter dictionary, retaining the native signal path; its displayed controls are only an editing projection. Chains receive fresh insert and nested pitch identities. Chain application targets different media, so it clears source baked ranges; omitting automation also clears manual pitch edits and the manual-only gate. Chain files retain represented source fields for interchange, while preparation applies this target-media policy. Only **Apply** changes the server project and participates in project Undo; private-library operations do not. These workflows have pure state/codec regressions, while actual native file interoperability, modal/focus/large-text review and browser/server interaction remain acceptance gates. Presets are shared through exported files, not a live server registry.

The browser declares `compact-control-patches` only after an authenticated host advertises the feature and `client.features` operation. Scalar mixer deltas preserve clips, routing, inserts and even dense automation arrays by identity. Unnegotiated hosts continue to send full controls; no host capability is assumed from the client version.

Workspace shortcuts leave native button/field activation, content editing, IME composition and consumed events alone. Space from the Designer, Pitch or effect chart toggles only its workspace and ignores key-repeat; Space on a focused action button activates that button once. Virtual keyboard buttons support held Enter/Space notes with release on key-up or blur, in addition to pointer input and labelled typing keys. Opening the controller chart releases held Designer notes. Native modal dialogs retain their Tab trap and return focus to a connected opener, or to an open parent/private timeline if a mixer rerender removed it. These behaviors have pure event/state regressions; actual browser keyboard-only, focus, Escape and screen-reader acceptance remains queued.

Native preset names use `Intl.Segmenter` extended grapheme counts and grapheme-safe collision suffixes, matching Swift’s 80-character rule for tested combining/emoji names. Older engines lacking Segmenter decline this interchange rather than truncate valid native names. Naming collision regressions cover Foundation’s tested POSIX case/diacritic folding, including sharp-s, ligatures and sigma while retaining Indic/Hebrew marks and emoji variation selectors. Foundation currently rejects Unicode control/format scalars such as ZWJ in preset names; the browser follows that existing policy. [Apple’s CFStringFold documentation](https://developer.apple.com/documentation/corefoundation/cfstringfold(_:_:_:)) and [Unicode’s case-folding data](https://www.unicode.org/Public/UCD/latest/ucd/CaseFolding.txt) describe the intended equivalences. Browser/native Unicode-version differences remain part of cross-language acceptance rather than a blanket equivalence claim.

The controller chart indexes each lane after edits and uses binary viewport bounds for drawing and pointer hit tests, retaining the held predecessor without rescanning a long prefix. A 100,000-event pure regression checks logarithmic lookup and identity preservation; fine-zoom hit testing uses the unsnapped pointer position before creating a snapped new point. This algorithm check does not replace measured browser frame-time acceptance.

Keyboard-only chart navigation now uses Home/End for first/last and plain brackets for previous/next targets in Pitch, Designer and controller lanes. Designer supports Control/Command A to select all notes. Selection announcements include note/beat/value, and navigation reveals off-screen targets in this private viewport. Selection does not create project or draft Undo entries and never sends a server edit; subsequent arrow-key or numeric adjustment remains explicit.

Automation gestures capture their track identity and observed track revision at the start. The sender carries that exact expected version; a foreign edit before sending, a changed selection, missing target metadata after a receipt, or newer foreign metadata after acceptance stops the gesture without adopting that version. Only an exact own receipt plus its installed target version advances it; verified no-op curves retain their existing target version. Conflicting/rejected/uncertain curves remain private, shown in amber, and **Reload lane** explicitly discards that draft for review. Switching lanes fences late results and cancels unsent old-lane values. Tests cover both reply/metadata orders, coalescing, conflicts, uncertainty, no-op receipts and late lane changes. Uncertain outcomes still require server reconciliation; Reload is not automatic replay.

Expanded effect gestures use the same exact own-receipt/target-metadata fence and pass their captured expected track revision. Accepted edits followed by newer foreign metadata retain the private settings for review rather than adopting the colleague’s version for another queued parameter change. Verified no-op comparisons normalize native Float32 parameter/curve scalars and default curves while keeping timeline frames exact; this avoids false conflicts on repeated values after native rounding.

Automation lanes also support Home/End and bracket navigation. Selecting an off-screen point reveals it in the private arrangement viewport and suspends Follow; numeric controls enable only for a selected editable point. A conflicting retained draft remains browseable but blocked for editing, and selection announcements retain its review warning.

Designer/Beats drafts pin the opening track, generated clip, timeline frame, observed version and connection epoch. Insertion sends the captured version and never follows a changed background selection. A changed/deleted target, reconnect, unconfirmed insertion or newer foreign metadata preserves the private pattern for review. **Reload source** explicitly discards/reloads the original editable clip; **Insert as new track** explicitly detaches the draft from the old destination. Existing generated clips retain their tempo when opened; new patterns use arrangement tempo. Double insertion is blocked, empty drum patterns stay editable, and late replies/cleanup cannot close or stop a reopened workspace. If editing continues while an earlier pattern is inserted, the newer private pattern remains open. These source/state regressions do not substitute for native/browser interaction acceptance.

Pitch targets are pinned to their source version and connection. Rejected, uncertain, or superseded edits remain private and cannot be baked; Analyze explicitly reviews the current source before replacing an unconfirmed draft. Analysis and bake results cannot close or update a reopened editor. Automated tests cover these ownership races; desktop interaction acceptance remains queued.

Master proposals capture the arrangement, Master rack revision, and connection before entering the request queue. A foreign change, unconfirmed application, or late result keeps the private proposal for review. Newer manual settings remain editable and are not replaced by a generated response; Apply is fenced to the captured Master version. These races have pure module regression coverage; actual desktop acceptance remains queued.

Expanded effect and saved-chain edits also carry opening-generation and connection fences. A queued preset, chain, bake, or workspace-navigation result cannot target a reopened editor. Automation gestures preserve private curves across reconnects even when the server happens to reuse the same track revision number.

Live automation client groundwork uses the canonical server-stamped Write contract. Read/Touch is private per track and parameter; Touch requires the advertised `automation-write` feature, all four operations, operator authority, and a valid playing source. Volume/pan faders, precision effect sliders and continuous parameter fields route through owner-bound leases; legacy recipe inserts expose their amount lane. Discrete controls, legacy named parameters, unsupported manual pitch targets, and the extended unautomated volume range remain unavailable. No browser playhead or display timestamp creates automation points.

Values use one acknowledged request plus the latest pending value. Releasing a control reserves one final-value slot and End; keyboard repeats remain one gesture until key-up. Owner Stop events may finalize a gesture without another client-authored End. A control-enqueued or finalizing result remains pending; only a committed owner receipt and matching installed resource version show a confirmed recording. Rejection, uncertainty, reconnect, or newer foreign metadata retains reviewable outcomes without replay.

Review recordings requests the original owner draft, streams at most 256 KiB per chunk, verifies SHA-256 and the typed artifact's source/summary/clock proof, and decodes it in a dedicated worker. Full original curves stay off the UI thread; bounded plots show actual ramp starts and requested targets, with truthful interruption/incomplete labels. Export saves the verified native draft JSON. Review/export never reapply it. Write capability remains hidden on unqualified hosts; end-to-end callback replay, one authored Undo, desktop interaction, hardware/listening checks, cycle writing and deliberate draft reapplication remain open gates.

When an isolated worktree consumes a newer canonical protocol checkpoint, run tests with `SOUNDROOM_PROTOCOL_SOURCE=/absolute/path/to/current/protocol`. Normal integrated tests compare browser generated files and grammar helpers directly with this checkout's canonical `protocol/` files. `node web/tools/sync-contract.mjs` copies these artifacts with only JavaScript import suffix normalization.

A Seek or output restart may report a new audio-clock epoch when ending a lease. The client accepts that only as noncommitted terminal status. Saved-prefix proof must retain the original capture epoch; an artifact with no original-epoch release remains explicitly incomplete.

### Live Write acceptance against the portable service

`web/tests/live/run.sh` builds `write_acceptance_host` (real portable service and verified TLS endpoint with a simulated, timestamped callback; it opens no audio device) and drives the unmodified SDK, mirror, Write controller, Touch pointer/keyboard bindings and draft worker against it under Node. It uses the private fixture in `build/CrossPlatformBaseline/web-tls` (override with `SOUNDROOM_TLS_FIXTURE`) and trusts its CA for that Node process only; system trust is unchanged. This qualifies wire, authority, driver and receipt behaviour end to end, not DOM interaction, accessibility, hardware timing or listening.
