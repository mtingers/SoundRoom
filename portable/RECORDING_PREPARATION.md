# Portable recording preparation

The engine now has worker-side recording components with deterministic simulated-clock qualification. They do not enable the server's Record capability, open audio devices, replace the Mac engine, or establish hardware synchronization. Physical input/output qualification remains queued.

## Ownership and integration

1. A server control worker explicitly resolves device UIDs and creates each native-rate `CaptureWriter`/`CaptureReader` pair. Existing Core Audio input/output adapters remain hardware-unqualified. Never enumerate or open them merely because a client connects.
2. The physical output callback calls `AudioHost::render_timed` with its actual device sample/host timestamp. `GraphControl::output_anchor` coherently returns the first advancing unwrapped graph frame, actual timestamp, advancing frame count and run epoch. Ordinary `render` supplies no timestamps. Settled paused callbacks return no anchor. An immediate seek changes epoch; sample-aligned live edits preserve it. Immediate seek adoption occurs at a hardware callback boundary.
3. A dedicated worker per input creates `CaptureArchive`, `CaptureAligner` and `RecordingSourceWorker`. All sources receive the same actual output anchors from the control worker. Use the backend's host-tick scale (macOS `host_ticks_per_second`) and the same host domain for input/output. Polling duplicate anchors is harmless. Network/client timers are never substituted for audio timestamps.
4. The source worker archives a complete native packet before alignment/conversion. Its resampler has a fixed planar ring and prepared filter; no file IO, clock fitting or resampling occurs on the audio callback. Drain output after each packet and apply `route_track` to each track's mono/stereo native-channel selection. Multiple tracks can share one input source; separate physical devices need separate clock fits/resamplers/archives.
5. Call `observe_capture_health` on the queue's actual health snapshots, including after the final drain. This retains final dropped-packet/device-fault evidence even when no later packet exists to expose a sequence gap. Persist archives with worker `sync` calls at a bounded interval. On stop, finish conversion, drain the received prefix, then finish the archive.
6. The authenticated service owns punch/count-in policy, track routing persistence, asset paths, latency calibration, disk/global resource admission, durable take identity, uncertainty recovery, authored undo and final project/take commit. A raw `completion.json` means packet writing completed; it is not permission to promote a suspended or gapped take to complete recorded audio. The worker reports suspension and the archive journal retains its cause. Any recording command remains unavailable until these authority paths and the physical gates pass.

## Native stop, producer sealing and raw custody

The Mac input adapter now exposes `health()` and `stop_and_seal()`. Native Start success sets `running`; usable recording readiness still requires actual timestamped accepted PCM, a current output clock anchor, worker alignment and authority/resource admission. A request-time timer or native Start return alone is not a recording acknowledgment.

`stop_and_seal()` calls the native stop operation and propagates errors. After success, it closes the callback scope to future entries and returns `None` while an admitted callback is still finishing. The control worker polls; callbacks never wait, sleep, allocate or perform disk work. Callback admission happens before mutable buffer/writer references are formed. Unexpected reentry is rejected without touching the unit-owned buffers; rejected callback/frame counts remain explicit health evidence. Successful quiescence seals the queue irreversibly. A new take requires a fresh queue/unit scope. Late callbacks cannot mutate the sealed counters or PCM. Teardown preserves native unit/context storage if stop or callback quiescence cannot be established; it does not dispose callback-owned state concurrently or produce an uncertain completion receipt.

Queue closure and native device stopping are distinct. `CaptureControl::seal()` fences only producer copies/fault-counter mutation; `final_stats()` is unavailable until an admitted mutation releases its fence. `CaptureReader::seal_receipt()` additionally requires every accepted queue packet to have been consumed. A stopped native receipt's `matches_capture()` binds it to that exact drained queue and final counters. Retained source identity is private and process-unique; it is not a client-supplied field.

Live raw workers use `RecordingSourceWorker::with_capture(..., &control)` to bind the source scope and native format. After native stop/quiescence, final queue drain and conversion/output drain, call `finish_archive_sealed(receipt)`. It rejects a foreign source, changed format, omitted accepted packet or nonfinite-count mismatch, observes final dropped-frame/device-fault counters and consumes/syncs the archive writer. Final lost packets are journaled even when no later packet exposes their source gap. Only then may the trusted hardware owner transfer the private raw directory to service recovery custody. The offline `finish_archive()` remains available for recovery/simulated sources and does not establish a live stop boundary.

Native rejected-frame/reentry health, stop errors, alignment suspension, queue gaps and nonfinite samples must remain separate review evidence. A completed raw-write receipt is not a complete or clean authored take. Automatic device-change detection/reconfiguration, capture-to-service owner lifecycle, aggregate resource admission and physical input/output acceptance remain open; this source checkpoint enables neither Record nor a wire operation. The documented native stop operation is [AudioOutputUnitStop](https://developer.apple.com/documentation/audiotoolbox/audiooutputunitstop(_:)); its successful return is combined with the adapter's own callback/producer fences rather than inferred from a client request.

Tests cover fake-native lifecycle, exact raw retention, final loss/fault, foreign-receipt, missing-prefix and zero-heap queue sealing. No actual device API is invoked by those fixtures.

## Clock behavior

`SampleClock` uses a fixed 64-observation centered regression with bounded rate/phase convergence. It differences native host tick integers before converting to floating point, preserving precision when a long-running host counter exceeds 2^53. Native sample/host validity flags, monotonic timestamps, rate bounds and output run continuity are required. Outliers over the admitted phase jitter are reported without moving the fit. A clock reset, incompatible output epoch, paused/discontinuous output clock, excessive drift or stale output anchor rejects alignment.

`CaptureAligner` reports fractional output placement, input/output sample ratio, queue gaps and additional device sample-clock gaps. Output placement is unwrapped even when the visible session loops. A calibration offset is explicit and bounded to 30 seconds. The engine does not guess physical ADC/DAC/driver latency; timestamp reference accuracy and calibration require hardware checks.

`CaptureResampler` uses DC-normalized Kaiser-windowed sinc interpolation with 2,048 fractional phases and linearly interpolated coefficients. Filter support scales with the downsampling ratio, keeping upper passband and stopband quality at 192/384 kHz input. Its prepared source ring is 32,768 frames/channel; input/output blocks are bounded at 8,192 frames and 1–64 channels. Native rates 8–384 kHz convert to the session's 48 kHz. Phase and ratio follow mapped device clocks smoothly rather than stepping at packet boundaries. A gap requires an explicit new segment; conversion never hides it with interpolated audio. Final zero padding is filter context only, and output ends at the received native exclusive end.

Prepared PCM/filter byte counts are exposed for authority admission. Filters occupy about 3.00 MiB at 44.1/48 kHz through 24.02 MiB at 384 kHz, including weight scratch; source PCM is 128 KiB/channel. CPU cost increases with channel count and downsampling ratio. The offline benchmark is useful sizing evidence, not deadline or simultaneous-session qualification.

## Raw retention and recovery

A new exclusive private archive directory contains immutable `manifest.json`, append-only `native.packets`, append-only `events.jsonl`, and a final raw-write completion receipt. Native packets retain all input channels, exact Float32 bits (including nonfinite values), queue source sequence, native sample time, host ticks and validity flags. Header/payload CRCs detect corruption. The aligned worker separately substitutes zero for nonfinite samples and reports the count; raw packets remain bit-exact.

Output clock anchors, queue/device gaps, final queue overruns, worker overruns, timestamp outliers, resets, nonfinite samples and device faults are journaled. `CaptureArchiveReader` recovers complete validated packets from a bounded stream and explicitly identifies an interrupted final header/PCM tail. A corrupt complete packet stops scanning. `CaptureEventReader` bounds each JSON event to 16 KiB and the journal to 512 MiB/1,000,000 events; an incomplete final JSON event is an explicit tail. Recovery never interprets tail bytes as samples, automatically deletes raw data, or conceals loss with synthetic silence.

Archive creation and recovery now use the shared [private directory provider](PRIVATE_STORAGE.md) with retained handles, owner/ACL admission, single-link regular files and exclusive descendant creation. Mac filesystem/ACL/path-replacement checks pass. Windows/Linux target runtime and durability, disk-full fault injection and authority recovery remain qualification gates. The service must retain admitted roots, immutable raw leases and idempotent take/asset identities before exposing recording.

## Deterministic evidence

`tests/capture.rs` uses simulated clocks and mathematically bandlimited signals, not recorded microphone data or a copied resampler implementation. It verifies independently drifting input/output clocks; jitter/outlier/reset/gap behavior; fractional placement; carried filter phase; packet partition invariance at 8, 44.1, 48, 96, 192 and 384 kHz; lower/upper passband accuracy; downsampling alias rejection; invalid/overrun bounds; exact raw packet recovery; every truncation point of a final packet; corrupted PCM; final missing-packet/device-fault reporting; event recovery; and retained raw audio after alignment suspension. Realtime allocation probes include actual-timestamp publication, aligned-edit continuity and seek/pause epochs.

Software fixtures cover clock fitting and offline throughput without invoking the hardware backend.

## Aligned artifacts and authored import preparation

`capture_recovery::recover_take` replays immutable native packets and the actual sequenced output anchor journal on a worker. `RecoveryPlan` selects mono/stereo routes, calibration inherited from the archive, optional punch range, optional loop range, admitted drift and explicit incomplete-capture policy. Output clock anchors now retain the source worker's consumed native end at observation, allowing recovery to replay exactly the clock history available to the live worker. Older unsequenced anchors remain raw evidence and require review; recovery does not fabricate their alignment.

The worker streams 48 kHz stereo float WAVs with patched/synced final RIFF lengths. It creates separate clips at native queue/device gaps and input clock resets, separate takes at output epochs and loop passes, trims only the chosen timeline range, and retains all native preroll/raw audio. It does not fill gaps with synthetic audio. Interrupted headers, PCM or journals produce explicit review metadata and only verified received prefixes. Nonfinite sample counts, tail byte counts and original typed device/overrun events remain distinct. Empty/unplaceable captures require review.

A private staging directory is published with an exclusive directory commit only after every WAV, artifact digest and receipt is complete. Cancellation/failure leaves the raw archive untouched. The report carries content-derived UUID identities, source/plan fingerprints, relative artifact paths, WAV fingerprints, model-compatible `Take`/`Clip` data and structured issues. A retry returns `AlreadyPresent` only when raw content, settings, committed WAVs and the checksummed receipt all agree. Concurrent identical jobs produce one committed result; changed identity content rejects. The service must lease raw data immutable during recovery; the worker also checks the raw fingerprint before and after rendering.

`prepare_take_import` clones only affected current tracks and adds recovered takes while preserving active clips, mixer settings, automation, effects and clip history. Exact existing take identities produce no change; missing target tracks or changed/reused identities reject. `RecoveryAcceptance::ReviewedIncomplete` is a server-selected policy after review, never an untrusted client flag. This helper does not register assets, mutate a session/revision, authenticate users or commit an authored transaction. The service must do those atomically with expected track revisions, durable job receipts and its qualified private storage provider.

Recovery is available as an offline worker/CLI on this Mac and through `recover_take_in` on held private directory capabilities. Windows source integrates explicit protected-ACL creation and handle-rooted I/O; the previous blanket unsupported-storage branch is removed. Actual Windows/Linux target execution and storage crash durability remain open, including Windows namespace durability after flushed-file handle rename. The service must admit aggregate prepared filter/source/output PCM, raw decoder buffers, metadata (maximum 16 MiB receipt), up to 128 routed WAV handles and a maximum 4,096 assets/8,192 issues. Resampling remains off callback. No network recovery endpoint or Record capability is enabled by these helpers.

```sh
cargo run --manifest-path portable/Cargo.toml --locked --release \
  -p soundroom-engine --example recover_capture -- RAW_ARCHIVE NEW_ARTIFACT_DIRECTORY PLAN.json
```

The source must be immutable and both paths owned by the invoking user/service. The command prints the receipt; it does not edit a running session. Fixed continuous/gap/loop-punch references are retained under `fixtures/capture/`.

The [Mac native custody prerequisite](CAPTURE_CUSTODY.md) combines an opaque stopped native source with its exact sealed/drained queue, durable raw archive and incremental artifact seals; native rejection/untimestamped/failed-stop evidence remains reviewable. A fixed four-context admission bounds uncertain native input retention. Service Record activation and physical checks remain gated.
