# Soundroom Rust workspace

The Rust engine and server are the native macOS GUI's default audio backend. This workspace also contains a shared client library, terminal client, platform adapters, conversion tools, and regression fixtures. Other platform hardware backends remain experimental.

For the complete macOS app, use [the root build instructions](../BUILDING.md). To compile just the server:

```sh
cargo build --release --locked --manifest-path portable/Cargo.toml -p soundroom-server
```

Run that command from the repository root. From this directory, omit `--manifest-path portable/Cargo.toml`.

```sh
cargo test --release --locked --manifest-path portable/Cargo.toml -p soundroom-engine -p soundroom-server
cargo clippy --release --locked --manifest-path portable/Cargo.toml -p soundroom-engine -p soundroom-server --all-targets -- -D warnings
```

The `fixtures/` audio/project/MIDI files are regression references generated by Soundroom. They are needed by tests and are not user recordings. [Fixture documentation](fixtures/README.md) explains their generation and scope. `tools/` includes reference generators and optional recorded-instrument/drum importers. `crates/server/catalog/` contains public effect and instrument metadata used by the protocol.

Design details: [media formats](MEDIA_FORMATS.md), [private storage](PRIVATE_STORAGE.md), [recording preparation](RECORDING_PREPARATION.md), [capture custody](CAPTURE_CUSTODY.md), [recovery authority](RECOVERY_AUTHORITY.md), [compact controls](COMPACT_CONTROLS.md), and [automation write](AUTOMATION_WRITE_ENGINE.md).

Software parity/allocation tests do not replace hardware deadline, routing, capture-clock, or listening qualification. Optional Python model separation is documented in [BUILDING.md](../BUILDING.md); the server and ordinary audio effects do not require Python.
